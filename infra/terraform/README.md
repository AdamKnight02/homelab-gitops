# Multi-Cloud PKI Lab — Terraform Infrastructure

## Overview

This directory contains Terraform code for deploying a reproducible PKI platform across Azure and AWS. The local homelab remains the persistent environment; cloud deployments are reproducible architecture targets.

## Architecture Philosophy

```
LOCAL HOMELAB (Persistent)
    |
    +---- Azure (Reproducible Target)
    |
    +---- AWS (Reproducible Target)
```

- **Terraform First**: All infrastructure is defined as code
- **VM + K3s**: Preferred over managed Kubernetes for cost and similarity to homelab
- **Argo CD GitOps**: Platform workloads deployed via GitOps, not Terraform
- **No Secrets in Code**: Cloud-init contains no credentials; all secrets applied post-boot
- **Cost Conscious**: Default configurations minimize cloud spend

## Environment Separation

We use **directory-based separation** (not Terraform workspaces):

| Environment | Directory | State File |
|-------------|-----------|------------|
| Azure Lab | `infra/terraform/azure/` | `azure/terraform.tfstate` |
| AWS Lab | `infra/terraform/aws/` | `aws/terraform.tfstate` |

**Rationale**: Workspaces are error-prone for labs. Separate directories prevent accidental cross-environment operations.

## State Management

**Current**: Local state files (`.tfstate`)

**Production Options** (documented, not deployed):
- Azure: Azure Blob Storage with SAS token
- AWS: S3 + DynamoDB for locking
- Generic: Terraform Cloud, HCP Terraform

## Usage

### Azure (PLAN-ONLY)

```bash
cd infra/terraform/azure
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with your values

terraform init
terraform validate
terraform plan -out=azure.tfplan
# DO NOT RUN: terraform apply
```

### AWS (PLAN-ONLY or Ephemeral Test)

```bash
cd infra/terraform/aws
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with your values

terraform init
terraform validate
terraform plan -out=aws.tfplan
# Only apply if free-tier eligibility is confirmed:
# terraform apply aws.tfplan
# terraform destroy
```

## Security

- SSH keys are auto-generated by Terraform (ED25519)
- No inbound SSH by default (use cloud serial console or Session Manager)
- NSG/Security Group deny-all inbound by default
- Terraform state contains sensitive data — never commit it
- Cloud-init contains no secrets

## GitOps Integration

Terraform creates infrastructure (VM, network, IAM).
Cloud-init installs K3s and Argo CD.
Argo CD syncs the Git repository and deploys PKI workloads.

```
Terraform
    |
    +---- VM
         |
         v
        K3s
         |
         v
      Argo CD
         |
         v
      Git Repo
         |
         v
      PKI Platform
```
